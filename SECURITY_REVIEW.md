# Dependency and application security review

Reviewed 2026-10-11 against the installed lockfile and upstream source. Both `npm audit --json` and `npm audit --omit=dev --json` report **11 moderate, 0 high, 0 critical** affected package entries. These are four underlying advisories plus inherited dependency-chain findings, not eleven independent exploits. All are included in the production installation because rustplus.js bundles pairing/camera dependencies; none is development-only.

`npm audit fix --dry-run --json` proposed **0 changed / 0 removed packages** and retained all 11 findings (optional packages for other platforms were listed as additions). No safe compatible fix was available from that operation. No dependency versions, lockfile or Rust+ protocol library were changed. Existing protobufjs, form-data and qs security overrides remain.

## Application findings

- Server-side member fetches and role checks protect every switch/confirmation interaction; forged component IDs cannot select unregistered entities or bypass sensitive confirmations. Confirmations are user-bound, single-use and expire after 30 seconds.
- Operator `@everyone` is rejected in initial environment configuration and role-add settings. Authorization also ignores any legacy persisted `@everyone` entry; administrators can remove that entry with role-remove. Ordinary server administrators and the configured initial administrator retain the intended access.
- Discord sends suppress implicit mentions. Only actual/simulated raid messages may ping the configured raid role; recovery and connectivity notices never ping it. User names/text are escaped or sanitized.
- Source inspection found no hardcoded login tokens and no Discord-to-shell/eval path. SQLite inputs use bound parameters. Logs record controlled messages and sanitized codes rather than raw transport packets, URLs or tokens.
- `.env`, default pairing credentials, `*pairing*.json`, data directories and SQLite files are excluded from Git and the Docker context. Arbitrarily named custom pairing files must still be kept outside the project; ignore patterns cannot infer every secret filename.
- Docker runs as UID 1000, drops capabilities, disallows new privileges, exposes no ports and persists a named SQLite volume. The bot performs desktop pairing separately and stores no Steam password.

Residual operational risk: Discord notification delivery is at-least-once, offline alarm edges cannot be reconstructed, and sufficiently long outages can outlive Rust's retained chat history. These limitations are documented rather than converted into fabricated events or automatic uncertain-write retries.
